# Annotation Guidelines as Skill Orchestration

（第一篇：一种"决定式"的 harness，用于高度程式化、但仍有部分规则解决不了的任务，并留出自动提升的空间。UMR 上的实现是 umr-tree。）

## Introduction

为执行或分析特定任务，人们常常需要设计专用的 ontology，比如意图识别和意图分类用的标签体系，或者 UMR 这样的语义表示，以便对任务做更细的控制。传统上，这类数据要由大量标注员按照 guideline 一句一句地标；积累了足够的数据之后，才可能用它来训练模型。所以起步阶段的数据生产严重依赖人工，又慢又贵。【引用】

这类标注任务有一个特点：**高度程式化，但不能完全程式化**。以 UMR 为例，大部分工作有固定的流程和确定的规则：先切分句子，再给每一块找谓词和论元，名词短语和命名实体各有固定写法，同一个指称要合并成一个节点，图要合法、每个词都要覆盖到，文档层要对每句补上时间、模态和共指。这些都可以写成规则。但流程中仍有一些点是规则解决不了的：这个词是事件还是实体？该选哪个 PropBank 义项？这里的 aspect 是 state 还是 performance？这些判断要靠语言理解，过去只能交给人。

现有方法往往落在两个极端。纯规则系统把流程和判断都写成规则，在需要语言理解的地方很脆弱。【引用：规则 / 转换式 parser】通用的 agent harness（例如编程 agent）则相反，把流程也交给模型：下一步做什么、调用什么工具、输出什么格式，全由模型临场决定。对一个流程本来已经确定的任务来说，这样做既浪费又难控制：调用次数和成本不可预测，输出格式要靠模型自觉，出了错也很难知道是哪一步错的，而且只有最强的模型才撑得住。

我们提出一种"决定式"的 harness：**流程由 harness 确定地执行，模型只在规则解决不了的地方做决定。** 具体来说，我们把 guideline 改写成一组 skill。每个 skill 是流程里的一个节点，写明输入、判断依据、例子和输出 schema。规则能处理的节点（重入合并、覆盖检查、图的拼接和合法性）直接由程序完成，不调用模型；需要语言判断的节点（句子类型、谓词和论元、名词短语、命名实体、文档关系）才调用模型，而模型的输出是受 schema 约束的结构化决定，例如从有限选项中选一个类型，或者填一个图片段。下一步走向哪个 skill，由 registry 根据这个决定确定地分派。【核：这里的"决定式"是不是你想表达的意思，英文可以写成 decision-driven 或 deterministic orchestration】

这样的设计带来三个好处：

1. **可解释、可调试**：每个节点的输入、决定和输出都保留下来，一个错误可以追溯到具体是哪个 skill、在哪一步做的决定，我们因此能按 skill 统计丢了多少分；
2. **格式保证正确**：整张图由程序按片段拼接，变量、括号、角色名的合法性由规则保证，模型从不直接写完整的 PENMAN；
3. **小模型也能做**：每个决定都很局部，本地的小模型也能完成。用 Qwen3.5-9B 时，每句一次调用、只给 guideline 的基线句子 F 全部为 0；给出详细说明的单次生成，多数文档也只有 3～8 F；同一个模型走这个 harness 能达到 12～24 F。换成 Qwen3.8-27B，种子 skill 在中文 0001～0004 上达到 39～47 F，和 Sonnet 的 50 F 已相差不远。【待核：Qwen-9B 用的是 0008～0032，和 Sonnet 不是同一批文档】

决定式的结构也给**自动提升留出了空间**。规则部分是固定的，会出错的只有模型做决定的那些节点，而每个这样的节点都是一个有名字、有独立说明的 skill。人工维护 guideline 时，每发现一类错误就往书里加一条规则，久而久之会变成上千条彼此纠缠的规则。【引用：1995 年的规则学习；ACL 2026 的 heuristic learning】在我们的 harness 里，改进可以交给模型自己完成（RSI）：对照少量 gold 文档逐句找出差异，借助节点记录把问题定位到做出那个决定的 skill，再只对这个 skill 的说明和例子做"改、增、删"，不会牵动流程和其他 skill。在中文 UMR 上，以 Claude Sonnet 解析、Claude Opus 反思，只用 2 篇训练文档，测试集（0004+0005）的句子 F 就从 45.5 提高到 52.9，每句一次调用的基线为 32.9。

我们也分析这种设计的边界。决定点越细，调用次数就越多：用前沿模型时每句几十次调用，约 $0.7。流程是串联的，上游的决定一旦错了，下游节点都在错误的输入上工作。自我改进在强模型上几轮之后趋于平稳；在弱模型上，改动本身的质量不够，甚至会让分数下降：Qwen-9B 反思后的版本，平均比种子低 1.4 F。【可选：这一段要不要保留，或者移到分析一节】

本文的贡献如下：

- 提出一种决定式的 harness，面向高度程式化、但仍有部分内容规则解决不了的标注任务：流程和合法性由规则确定地执行，模型只在规则解决不了的节点上做受 schema 约束的决定；
- 在中英文 UMR 上实现这一 harness（umr-tree），覆盖句子图和文档级的时间、模态、共指，证明它能让 9B～27B 的本地模型产出可用的标注，而这些模型直接生成时几乎完全失败；
- 利用决定点的可定位性，提出按 skill 定位错误并局部修改的自我改进方法，并分析它在不同强度模型上的收益和局限。
