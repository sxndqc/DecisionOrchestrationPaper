\section{Methodology: Decision Orchestration}
\label{sec:method}

\paragraph{Workflow and components.}
A registry runs rule nodes and decision nodes to produce an annotation and an execution trace. On gold data, a judge scores individual annotation units, and a reflector uses the scores and trace to revise the procedure. We represent this system as
\begin{equation}
\label{eq:procedure}
\begin{aligned}
\Pi &= (\mathcal{S}, R, C, M, \theta, J, \mathcal{F}),\\
s_i &= (I_i,O_i,d_i,T_i)\in\mathcal{S},\\
\mathcal{F} &= (F_{\mathrm{diag}},F_{\mathrm{valid}},F_{\mathrm{comp}}).
\end{aligned}
\end{equation}
Here, $\mathcal{S}$ contains decision nodes $s_i$, each implemented as a skill with input and output schemas $I_i,O_i$, instructions $d_i$, and available tools $T_i$. $R$ is the registry, $C$ the deterministic code, $M$ the fixed annotation and reflection models, and $\theta$ numerical parameters such as thresholds. $J$ is the fine-grained judge; $\mathcal{F}$ comprises diagnosis, edit validation and compression.

$R$ executes nodes in ordered groups (\emph{waves}), dispatching a rule node in $C$ or a decision node in $\mathcal{S}$ from typed outputs (\emph{emits}). At $s_i$, $M$ evaluates the input under $d_i$, with supporting information from $T_i$; $C$ validates or converts its answer to an emit conforming to $O_i$, using $\theta$ for closed decisions, and assembles the annotation. $J$ scores it against gold; $\mathcal{F}$ invokes a reflector in $M$ to locate errors and propose edits to the responsible instructions or code, then validates and compresses the revised procedure.

\paragraph{Decision modes.}
\label{sec:modes}
Decision nodes have two implementations with the same emit.
In \textbf{fragment mode}, an LLM reads the skill's instructions and input, uses its available tools, and returns a graph fragment, span list or relation list. Code validates fields, enumerations, span bounds and edge endpoints; invalid outputs are retried.
In \textbf{closed mode}, code enumerates options and asks choice, yes/no or graded questions. A decision model returns probabilities over these options, which rules convert into the emit using thresholds in $\theta$. Both modes log inputs and outputs; closed mode also records options and probabilities.

\paragraph{Threshold calibration.}
\label{sec:calibration}
To account for differences in model probabilities, we fit decision thresholds in $\theta$ by coordinate descent on training F: sweep each threshold over $\{0.2,0.3,\dots,0.8\}$ with the others fixed and keep a value if it improves F by more than 0.1. Calibration re-runs rules on cached answers without model calls.

\paragraph{Cascade.}
\label{sec:cascade}
For closed decisions with confidence $c=\max_o p(o)<\tau$, a stronger model receives the same state and options and replaces the original answer. The routing threshold $\tau$, included in $\theta$, is chosen on training data.

\paragraph{Fine-grained evaluation.}
\label{sec:evaluation}
The judge $J$ aligns predicted and gold units and assigns each a verdict (correct, partial, wrong, missing or extra) and credit: 1 for correct, check-specific partial credit, and 0 otherwise. It reports precision, recall and F1 separately for each check (\S\ref{sec:metrics}). Traces identify the skill call behind each predicted unit; missing gold units are flagged. Reflection receives these unit-level records and decisions. Aggregate task F1 is used for reporting and edit acceptance.

\paragraph{Reflection.}
\label{sec:reflect}
Each round uses five gold sentences and has three steps (Algorithm~\ref{alg:reflect}):
\textbf{Diagnose ($F_{\mathrm{diag}}$):} parse and judge the batch; the reflector reads gold, predictions, unit-level scores, attributed errors, decision traces and editable files to locate causes and propose additions, replacements or deletions.
\textbf{Validate ($F_{\mathrm{valid}}$):} in closed mode, apply each edit to a copy and re-parse the current and all earlier batches. Keep it if current-batch F improves and earlier-batch F falls by at most 0.5, or earlier-batch F improves without a current-batch loss; return rejected edits once with their measured effects. In fragment mode, accept edits that apply and leave the procedure loadable, then test them in the next round.
\textbf{Compress ($F_{\mathrm{comp}}$):} rewrite files exceeding $1.5\times$ their seed length, merging redundant rules while preserving options, questions and conventions; in closed mode, keep the rewrite only if neither batch set loses more than 0.5 F.
Each round freezes the revised procedure with a reviewable diff. Edits copying six consecutive Chinese characters or four English words from test text are rejected.
