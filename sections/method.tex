\paragraph{The tasks.}
Figure~\ref{fig:tasks} shows what the two schemes ask for. A \umr annotation of a sentence is a graph whose concepts must follow a lexicon (PropBank) and a large inventory of abstract concepts, roles and attributes, aligned to the tokens, and a document-level layer that links each event to a temporal anchor and a conceiver and each mention to its antecedent \citep{gysel2021design,bonn2025umr2}. A PARSEME annotation is a set of token groups, each with a category, decided by tests such as ``can a verbless noun phrase refer to the same event?'' \citep{ramisch2018parseme}. Both schemes are complex in the sense that matters for annotation: the guideline is long, its decisions depend on each other, and a correct annotation needs both general understanding of the sentence and the scheme's conventions.

\paragraph{Procedures, skills and the registry.}
Decision orchestration compiles the guideline into a procedure $\Pi$: a set of \emph{skills}, a \emph{registry} that dispatches them, and numeric parameters $\theta$. A skill has an input, an output schema (its \emph{emit}) and an implementation, either code (a \emph{rule node}) or a model call (a \emph{decision node}). The registry runs \emph{waves} in order; within a wave, a dispatcher maps fields of a skill's emit to the next skills, so control flow is a fixed function of typed decisions and no model can call an undeclared step. Figure~\ref{fig:walk} follows the \umr procedure through the sentence of Figure~\ref{fig:tasks}a. \skill{sent\_type} decides what a piece of the sentence is (several coordinated clauses, one predicate, a noun phrase, a named entity or date, or a leaf); \skill{predicate} chooses a head, its sense among the PropBank rolesets that code looked up, its aspect, modal strength and polarity, and the participant role of each word; every participant becomes a placeholder that goes back to \skill{sent\_type}; the rule node \skill{coverage} sends back words nothing took. A rule wave merges nodes that stand for the same thing, and the \skill{document} wave adds temporal, modal and coreference relations using the five previous sentences. The PARSEME procedure is the smallest instance: a rule node enumerates candidate token groups from the dependency tree of the input, a decision node judges each candidate, and the output is written by code.

\paragraph{Two decision modes.}
\label{sec:modes}
A decision node has two interchangeable implementations with the same emit.
In a \textbf{fragment decision}, an LLM reads the skill's instructions (the part of the guideline the step needs), the piece and the sentence, may look a lemma up in PropBank, and answers with its emit through a schema: a small graph fragment with placeholders, a list of parts, a relation list. The schema is the format constraint: fields and enumerations are fixed by the registry, spans must lie inside the piece, every variable of an edge must be a node or a placeholder, and an answer that does not validate goes back to the model; no call ever writes a whole graph. In a \textbf{closed decision}, the skill's code enumerates what the answer could be (the words of a piece, the rolesets of a verb, the options of the guideline with a one-line description each) and asks closed questions: a choice among options, yes/no, or a graded score. A \emph{decision model} returns a probability distribution over the options and no text; rules read the distributions against thresholds $\theta$ and build the emit (Figure~\ref{fig:walk}). Closed decisions need no model that can write structured text and come with probabilities, so they can be served by decision services \citep{typesafe2026jev,openai2026decisions,microsoft2026decision}, and every decision is logged with its alternatives.

\paragraph{Threshold calibration.}
\label{sec:calibration}
A rule like ``keep the candidate if $p(\text{yes})\geq 0.5$'' is written for some answerer, and another decision model spreads its probability mass differently. What matters is the decision the rule takes, so we fit $\theta$ to the task metric on the training sentences by coordinate descent: each threshold in turn is swept over $\{0.2, 0.3, \dots, 0.8\}$ with the others fixed, a value is kept when it raises training F by more than 0.1. Only the rules are re-run; cached answers make calibration nearly free.

\paragraph{Cascade.}
\label{sec:cascade}
Every closed answer carries a confidence $c=\max_o p(o)$. In the cascade, questions with $c<\tau$ are asked again, with the same state and options, of a small LLM (Claude Haiku 5.5) that must pick one of the options; its pick replaces the decision model's answer, and nothing else changes. $\tau$ is chosen on the training sentences.

\paragraph{Evaluation and reflection.}
\label{sec:reflect}
A parse is scored with the task's official metric and with a fine-grained judge that compares predicted and gold units (nodes, concepts, senses, attributes, arguments, roles, names, reentrancies, temporal, modal and coreference relations; \S\ref{sec:metrics}). Each predicted unit is attributed to the skill call that produced it, through the parse's trace, and each gold unit no call produced is marked as such. Reflection improves the procedure, never a model, one batch of five gold sentences at a time (Algorithm~\ref{alg:reflect}, appendix). For \umr, the five sentences are consecutive sentences of one document, so that coreference and temporal relations within the batch are kept; documents are otherwise broken up. A round has four steps. (1)~The batch is parsed with the current version and judged. (2)~A reflector LLM reads the gold and predicted annotations, the judge's differences with their skills, every decision with its options and probabilities, and the editable files, lists \emph{every} problem it finds (we set no limit) with its cause in the procedure, and proposes edits that modify, add or delete text in one file each. (3)~Acceptance. In closed mode a parse costs seconds, so each edit is measured: it is applied to a copy, the batch and all earlier batches are re-parsed, and it is kept if the batch improves while the earlier batches do not fall by more than 0.5 F, or the earlier batches improve while the batch does not fall; rejected edits go back to the reflector once with their measured effect. In fragment mode a parse costs minutes, so an edit is accepted if it applies and the procedure still loads, and the next round tests it. (4)~Compression: a file that has grown beyond 1.5 times its seed length is rewritten shorter by the reflector, merging rules and dropping redundant ones while keeping every option, question and convention; in closed mode the rewrite is measured like an edit. The result is a new frozen version, and its difference from the last is a readable diff. Edits that copy a stretch of test text (six Chinese characters or four English words) are refused.
