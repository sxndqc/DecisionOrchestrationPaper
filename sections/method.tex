\section{Methodology: Decision Orchestration}
\label{sec:method}

\paragraph{Procedure, skills, and registry.}
We encode an annotation guideline as
\begin{equation}
\label{eq:procedure}
\begin{aligned}
\Pi &= (\mathcal{S}, R, \theta),\\
\mathcal{S} &= \{s_i=(I_i,E_i,f_i)\}_{i=1}^{m},
\end{aligned}
\end{equation}
where each skill $s_i$ has an input schema $I_i$, an output schema $E_i$ (its \emph{emit}), and an implementation $f_i$: code for a \emph{rule node}, or a model call for a \emph{decision node}. The registry $R$ runs groups of skills (\emph{waves}) in order and dispatches subsequent skills from typed emits; $\theta$ contains decision thresholds. Code assembles the final annotation.

Figure~\ref{fig:walk} illustrates the \umr procedure: \skill{sent\_type} routes spans by type; \skill{predicate} chooses the head, PropBank sense, attributes and argument roles; argument placeholders and uncovered tokens return to \skill{sent\_type}. Later waves merge co-referring nodes and add document-level relations with the five preceding sentences as context. For PARSEME, code proposes token groups from dependencies, a decision node judges them, and code writes the output (Appendix~\ref{app:seeds}).

\paragraph{Decision modes.}
\label{sec:modes}
Decision nodes have two implementations with the same emit.
In \textbf{fragment mode}, an LLM reads the relevant guideline, input span and sentence, optionally queries PropBank, and returns a schema-checked graph fragment, span list or relation list. Validation checks fields and enumerations, span bounds, and edge endpoints; invalid answers are retried.
In \textbf{closed mode}, code enumerates options (e.g., heads, rolesets or attribute values) and asks choice, yes/no or graded questions. A decision model returns a probability distribution over these options, which rules convert into the emit using $\theta$. Both modes log each decision and its output; closed mode also records options and probabilities.

\paragraph{Threshold calibration.}
\label{sec:calibration}
To account for differences in decision models' probabilities, we fit $\theta$ by coordinate descent on training F: sweep each threshold over $\{0.2,0.3,\dots,0.8\}$ with the others fixed and keep a value if it improves F by more than 0.1. Calibration re-runs rules on cached answers without model calls.

\paragraph{Cascade.}
\label{sec:cascade}
For closed decisions with confidence $c=\max_o p(o)<\tau$, a stronger model receives the same state and options and picks an option to replace the original answer; $\tau$ is chosen on training data.

\paragraph{Evaluation and reflection.}
\label{sec:reflect}
A fine-grained judge compares predictions with gold, attributes predicted units to the skill calls that produced them, and marks missing gold units (\S\ref{sec:metrics}). Reflection revises the procedure from five gold sentences per round (Algorithm~\ref{alg:reflect}):
\textbf{Diagnose:} parse and judge the batch; a reflector reads gold, predictions, attributed errors, decision traces and editable files to identify causes and propose additions, replacements or deletions.
\textbf{Validate:} in closed mode, apply each edit to a copy and re-parse the current and all earlier batches. Keep it if current-batch F improves and earlier-batch F falls by at most 0.5, or earlier-batch F improves without a current-batch loss; return rejected edits once with their measured effects. In fragment mode, accept edits that apply and leave the procedure loadable, then test them in the next round.
\textbf{Compress:} rewrite files exceeding $1.5\times$ their seed length, merging redundant rules while preserving options, questions and conventions; in closed mode, keep the rewrite only if neither batch set loses more than 0.5 F.
Each round produces a frozen version with a reviewable diff. Edits copying six consecutive Chinese characters or four English words from test text are rejected.
